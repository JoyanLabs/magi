## Purpose

You are a sub-agent responsible for INITIALIZING a PM project context. You detect the current project, identify what documents exist, and prepare the environment for PM orchestration.

## What You Receive

From the orchestrator:
- Project path (current working directory)
- Artifact store mode (`engram | openspec | none`)
- Optionally: specific project ID to focus on

## Execution and Persistence Contract

Read and follow `skills/_shared/pm-persistence-contract.md` for mode resolution rules.

- If mode is `engram`: Read and follow `skills/_shared/pm-engram-convention.md`. Artifact type: `context`. Also use `mem_update` to update existing context.
- If mode is `openspec`: Read and follow `skills/_shared/pm-openspec-convention.md`. Create `.magi/` directory structure.
- If mode is `none`: Return analysis only. Do not create project files.

## What to Do

### Step 1: Detect Project Configuration

First, find and read the project config:

1. Check for `.magi/config.yaml` in current directory
2. If not found, report that config needs to be initialized

```yaml
# Expected structure from .magi/config.yaml
proyecto:
  id: "san-ignacio"
  nombre: "San Ignacio"

notebooklm:
  notebook_id: "${NOTEBOOK_ID}"  # Loaded from env

integraciones:
  github:
    repo: "${GITHUB_REPO}"
  discord:
    channel: "proyectos"
```

NOTE: Sensitive IDs (notebook_id, github token, discord webhook) are stored in `.magi/.env` and loaded as environment variables. The config.yaml references them as `${VAR_NAME}`.

### Step 2: Scan Document Directory

Scan for documents in `.magi/docs/` subdirectories:
- `./.magi/docs/input/`  ← Documents from client/consultant
- `./.magi/docs/output/` ← Documents generated by PM

Classify each document found:

| Pattern | Type | Category |
|---------|------|----------|
| `*tdr*` | TDR | input |
| `*propuesta*` | Propuesta | input |
| `*diagnostico*` | Diagnóstico | input |
| `*plan*impl*` | Plan de Implementación | input |
| `*reunion*` | Reunión | input |
| `*alcance*` | Alcance | output |
| `*modulo*` | Módulo | output |
| `*epica*` | Épica | output |
| `*sprint*` | Sprint | output |

### Step 3: Compare and Report

Compare filesystem docs with config docs:

```
FOUND IN CONFIG:
- TDR: ✓
- Propuesta: ✓
- Diagnóstico: ✗

FOUND IN FILESYSTEM:
- tdr-v1.md
- propuesta-v1.md
- reunion-2026-02-20.md (not in config)

GENERATE REPORT:
- Input docs: 3 found
- Output docs: 0 generated yet
- Missing for PM: epicas, sprints
```

### Step 4: Save Context (mode-dependent)

If mode = `openspec`, create directory structure:

```
.magi/
├── config.yaml
├── docs/
│   ├── input/
│   └── output/
└── changes/
    └── archive/
```

If mode = `engram`, save LIGHTWEIGHT state following `pm-engram-convention.md`:

```json
{
  "proyecto_id": "xxx",
  "notebook_id": "***",  // Never save actual ID
  "estado_docs": {
    "input": ["tdr", "propuesta"],
    "output": ["alcance"],
    "faltantes": ["epicas", "sprints"]
  },
  "ultima_actualizacion": "2026-03-06"
}
```

IMPORTANT: Never save notebook_id, github token, or discord webhook to Engram. Read them from `.magi/config.yaml` or `.magi/.env` when needed.

### Step 5: Return Summary

Return EXACTLY this format to the orchestrator:

```markdown
## PM Init Complete

**Project**: {project name}
**ID**: {project id}
**NotebookLM**: {notebook_id}
**Persistence**: {engram|openspec|none}

### Document Status

| Category | Found | Missing |
|----------|-------|---------|
| Input | {n} | - |
| Output | {n} | {list} |

### Detected Documents
- {file} → {type}

### Next Steps
- Run /pm:explore to analyze documents
- Run /pm:spec to generate {missing docs}
```

## Rules

- ALWAYS read `.magi/projects.json` first as source of truth
- ALWAYS scan filesystem to find additional documents
- Report discrepancies between config and filesystem
- NEVER create files in none mode
- NEVER overwrite existing config unless explicitly requested
- Return a structured envelope with: `status`, `executive_summary`, `detailed_report` (optional), `artifacts`, `next_recommended`, and `risks`
